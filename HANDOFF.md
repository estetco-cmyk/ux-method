# Передача: работа над методом

15.10.2026. Для чата, который продолжает работу над методом и не видел, как он появился.

## Что это

Метод проектирования взаимодействия человека с системой через интерфейс. Справка method-brief.md (версия 2) - рабочий инструмент: шаги 0-8 с выходами до первого экрана и чек-лист. method.md (версия 4.2) - основание.

Устройство: ядро для любой задачи и два профиля. Пошаговая игра - основной, проверен на Secredoku. Рабочий инструмент - набросок, проверен одним продуктом в два прогона.

## Как появился

Разбор путей игрока в игре Secredoku 13.10.2026 (репозиторий estetco-cmyk/Sudokulika, docs/flow-routes.md там) нашёл разрывы, которые не видны по отдельным кнопкам. Обсуждение с ChatGPT 13-14.10 подняло это до метода. Версии:

1. Пять слоёв проектирования и четыре вида информации, всё на примерах Secredoku.
2. Виды информации разведены по решениям игры, эвристики с контрпримерами.
3. Предмет и граница (геймдизайн задаёт трудность, метод проверяет интерфейс), цикл Нормана в трёх масштабах, инвентарь информации отдельно от решений о предъявлении, обратная связь как своя фаза.
4. Ядро для любой задачи, профили игры и инструмента. Справка.
4.1, 4.2. Транспорт через человека; переезд в этот репозиторий.

## Решения Анатолия, которые не пересматриваются без него

- Метод - не классификация элементов и не теория игрового опыта. Предмет - взаимодействие через интерфейс.
- Верхний уровень - цикл: ситуация и цель, восприятие и понимание, выбор и действие, результат и обратная связь, следующая ситуация. В трёх масштабах.
- Что есть информация (инвентарь) и как её показывать (предъявление) - разные вопросы, второе не выводится из первого.
- Основной профиль - пошаговые игры. Метод при этом должен работать с любой задачей.
- Таблиц и классификаций не добавлять без необходимости. Универсальных перебирателей состояний не писать: точечные сценарии.
- Каждое применение - через справку с обязательными выходами, а не чтением метода.

## Открыто

1. **Сверка вслепую.** Во втором прогоне стенда работ команда называла, что искать. Работает ли пункт 11 чек-листа без подсказки - нужен прогон на задаче, где ответа заранее никто не знает.
2. **Профиль инструмента** проверен одним продуктом. Нужен второй, лучше с несколькими людьми над одним объектом: там строки "чужие действия" и "несколько людей" ещё не испытаны.
3. **Профиль игры без единственного ответа** - тактическая стратегия - описан, но не прогнан.
4. **Порядок "проектирование нового"** не проверен: оба прогона - разбор существующего или почти готового.
5. **Ссылка на Нормана** без страницы и издания. Проверить по источнику перед тем, как метод уйдёт наружу.

## Как работать в этом репозитории

- Новый прогон - файлом runs/ГГГГ-ММ-ДД-имя.md: что за продукт, какой профиль, ответ чата дословно, что сработало, что пропущено, что поправлено в справке.
- Правка справки или метода - строкой в журнал в конце файла, версия растёт.
- Анатолий работает с git через GitHub Desktop, не через терминал. Ссылки на сайт GitHub - полными адресами.
